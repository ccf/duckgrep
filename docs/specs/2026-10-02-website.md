# duckgrep.dev: the landing page

## Goal

One page that gets a developer using a coding agent, or an engineering lead evaluating one, to install duckgrep. The measured savings are the reason to install, so they carry the page. Every number is real, keeps its scope and links to `bench/RESULTS.md`.

## Audience and success

- **Developers on a coding agent** decide in about a minute. Success: they reach the install block and leave with three lines (install, `claude mcp add`, the `CLAUDE.md` instruction).
- **Engineering leads** want cost and accuracy. Success: they find the table, its scope (494 structural questions, 3,620 runs) and the honest limits without leaving the page.

## Structure: "the race"

### First viewport

- The lockup, the tagline on two lines ("Grep finds strings." / "duckgrep answers questions."), the subhead, and the install command with a copy button.
- **Two terminals, side by side, on one real question** from the A/B run:
  - "Claude Code alone" replays its grep → read → grep calls.
  - "+ duckgrep" replays its `query(sql)` calls, with the result rows highlighted in match yellow.
- Under each terminal, counters for tool calls, tokens and cost tick as the replay runs, then freeze on the run's real totals.
- A caption names the question, the repo and commit, and says this run sits at the median saving (cost ×0.77 against a median of ×0.76), not the best case.

### The replayed runs

- **Main:** `flask-callers-show_server_banner` (Python). Alone: 3 calls, 26.7k tokens, $0.0182. With duckgrep: 2 calls, 22.7k tokens, $0.0141. Both answers are correct.
- **Second, behind a tab:** `ripgrep-two-hop-eprint_nothing_searched` (Rust). Alone: 3 calls, 27.6k tokens, $0.0204. With duckgrep: 2 calls, 23.0k tokens, $0.0159.
- Tool inputs and outputs come from the saved transcripts, trimmed only by cutting long output with a visible "…". The agent's final answer is shown in short.

### After the race

1. **The results table:** the average over all 494 structural questions, Python and Rust, Claude Code alone, + Serena and + duckgrep. It shows tool calls, round trips, tokens, cost and correct answers, with † marking differences that aren't significant. One line covers the unhinted numbers (used in 75% of runs; −12–19% calls, −14–18% cost). A link points to the method.
2. **Why it matters:** the four reasons from `brand/README.md`, in order.
3. **How it works:** index with tree-sitter into one DuckDB file, which refreshes before every query. Three short SQL examples with real output: callers, two hops and an outline.
4. **Install:** `uv tool install duckgrep`, then `claude mcp add duckgrep -- duckgrep mcp`, then the `CLAUDE.md` line. Each step has a copy button.
5. **Where it doesn't help:** localization from an issue report, and plain string search.
6. **FAQ:** `<details>`, a subset of the README's FAQ: what the agent can query, accuracy, freshness, Serena and language servers, and how the numbers were measured.
7. **Footer:** GitHub, PyPI, license and RESULTS.

## Behaviour and states

- The replay plays once when the race scrolls into view (IntersectionObserver), then offers "Replay". It never loops on its own.
- With reduced motion or JavaScript off, the terminals render their final state: all calls, all output and the frozen totals, with no animation. The page is complete without JavaScript, because the replay only animates content already in the HTML.
- Under 760px, the terminals stack, with "alone" first. The counters stay attached to their terminal.
- Light and dark themes come from the token set's `prefers-color-scheme` values. No toggle.
- The copy buttons use the clipboard API. Where it is missing, the text stays selectable.

## Build and hosting

- **Source:** `site/`, holding `index.html`, `site.css`, `site.js` (the replay, the tabs and the copy buttons) and `_headers` (security headers, which Cloudflare reads from the assets).
  - `site/tools/extract_replay.py` renders the race terminals from the gitignored transcripts straight into `index.html`, between `<!-- race:<id> -->` markers. Each step carries its time and running totals as `data-*` attributes. The page is committed with them, so the build never needs the transcripts.
- **Brand assets** are not duplicated. `site/build.sh` copies `site/` plus `brand/tokens.css`, `components.css`, `logos/`, `favicons/` and `social/` into `_site/` (gitignored). It only copies; nothing compiles.
- **Cloudflare Workers, static assets:** `wrangler.jsonc` serves `_site`. Workers Builds runs the build command `sh site/build.sh`, then `npx wrangler deploy` on `main` and `npx wrangler preview` for other branches (preview URLs). The domain is duckgrep.dev. Connecting the project and the domain is the owner's step. (This replaced Cloudflare Pages, which Cloudflare now calls legacy.) The page includes OG and Twitter card tags with `og-image-light.png`.
- **No framework and no bundler.** The only third-party script is Cloudflare Web Analytics, which Cloudflare injects at the edge (cookieless). The CSP allows exactly its beacon (`static.cloudflareinsights.com`) and its reporting endpoint (`cloudflareinsights.com`). The fonts come from Google Fonts through `tokens.css`, as the brand prescribes.

## Content rules

- `brand/README.md` is binding: the tagline verbatim, sentence case, no superlatives, exclamation marks or emoji. The simulated django multiples (22×, 110×) never appear as an agent's saving.
- **Absent and never invented:** users, testimonials, company logos, download counts, pricing and star counts.
- The install line assumes PyPI. If the site goes live before the package does, `build.sh` doesn't change it. The owner publishes first.

## Testing

- `tests/test_site.py`, which runs in the normal suite:
  - `build.sh` produces `_site/index.html`, and every local `href` and `src` resolves inside `_site`;
  - the replayed runs' final totals equal their records in `results.jsonl` when the records are present (otherwise it is skipped);
  - every number in the results table equals the README's table, which reports `bench/RESULTS.md`;
  - the `_headers` CSP hash matches the page's one inline script.
- **Manual:** desktop and phone screenshots in light and dark, reduced motion and JavaScript off, checked once, then the design detector and the finish review.

## Out of scope

Docs pages, a blog, a theme toggle and a changelog. Making the repo public, publishing to PyPI and setting up Cloudflare are the owner's actions.
